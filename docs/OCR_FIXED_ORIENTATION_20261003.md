# 2026-10-03 完整版 OCR 固定方向修复

## 更新原因

游戏截图中的文字方向固定，无需旋转 180°。PaddleOCR 的方向分类器曾把正向的五位战力数字判断为倒置，旋转后得到错误数字。原有范围校验会拒绝这些数字，而数字带识别出的五位候选又不能补空，最终留下缺失战力。

此次关闭方向分类来消除误旋转，保留原有战力保护规则。轻量版的战斗图像识别页仅为展示，本次不修改轻量版。

## 实现

- 主 PaddleOCR 引擎初始化使用 `use_angle_cls=False`，区域识别使用 `cls=False`。单行、批量数字带与多语言昵称识别原本已不进行方向分类。
- 保留本地分类模型目录参数与现有模型文件。当前 PaddleOCR 构造过程仍会检查模型目录，显式提供离线目录可避免联网准备模型；实际不创建或调用方向分类器。
- 战力范围、置信度、精读投票和合并规则不变。数字带五位候选仍不能填补空值，短于现有值的候选仍不能覆盖现有值。
- Excel 的“参赛阵容”战力列固定保留 P1–P5 五个位置。缺失位置显示“未识别”，后面的数值不会前移。ArenaData 明细与 JSON 继续使用原有数值及空值格式。
- 三个 OCR 入口均向原有运行日志写入 `power_anomaly=` JSON 行。仅记录战力缺失或候选冲突，包含源图、组/场、玩家 ID、攻守方、队/槽、最终角色名、初读原文与置信度、精读候选与支持度、两次数字带原文与置信度、最终值和拒绝原因。诊断复用已有识别结果，不增加 OCR 调用，不改变结果 JSON 的结构。
- 初始化日志记录 `ocr_angle_classification=False`，便于确认实际运行设置。

## 验证

- 三个无模型回归脚本共 19 项测试通过，覆盖方向分类开关、五位补空拒绝、六位数防短候选覆盖、五个导出位置与异常日志。
- 日志开关、战力开关、数字带开关与三种战力模式的 24 种组合，相对原实现输出一致；不识别阵容的后续赛段也保持兼容。
- 波莉所在完整对局五场的真实 GPU 回归：战力从空值恢复为 `98970`，其他战力、角色名、收藏、玩家信息、循环等级与胜负字段均与原结果一致。实际引擎未创建方向分类器。
- 真实 CPU 运行时识别波莉所在一整行，五个战力均与 GPU 一致，方向分类器同样未创建。
- 该国服赛季四张完整截图的 63 个对局块、315 场与 64 位参赛选手重新识别完成。相对原结果，逐字段仅有上述波莉战力一项改变，没有新增空战力或六位数缩短，其他字段全部一致。
- 两份上一赛季国服工作簿只读扫描后，复核其两个完整缺值对局块：阿妮斯恢复为 `99970`，安妮：奇迹仙女恢复为 `98970`。各五场仅对应空战力一项改变，其他字段一致。原工作簿、结果 JSON 与阵容 JSON 的哈希保持不变。
- 国际服 `3440x1440`、`1920x1080` 与港澳台 `2560x1440` 各一个完整对局块完成识别。首场玩家 ID、战力与胜方均与截图核对一致；港澳台昵称的繁简字形按现有中文模型输出。
- 新旧国服赛季工作簿的原生内容对照仅改变波莉的明细战力单元格和对应阵容战力单元格。公式、格式、列宽、行高、冻结与过滤等结构均不变，局部渲染确认五个战力位置完整显示。
